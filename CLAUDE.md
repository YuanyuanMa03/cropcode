# CLAUDE.md

This file provides guidance for Claude Code when working with code in this repository.

## Project Overview

CropCode is an open-source AI coding agent CLI (think Claude Code, but multi-provider and MIT-licensed), built with TypeScript + React (Ink TUI). It talks to LLMs through OpenAI-compatible APIs (DeepSeek, Zhipu GLM, Qwen, Xiaomi MiMo), and supports tools (Bash, Read/Write/Edit, Grep, Glob, WebSearch, AskUserQuestion, UpdatePlan), MCP integration, hooks, session management with context compaction, and a community skill marketplace.

## Repository Structure

npm workspaces monorepo:

- `packages/core` (`@YuanyuanMa03/cropcode-core`) — headless core library:
  - `src/session.ts` — SessionManager: session lifecycle, context compaction (auto/reactive/micro), permission computation, tool execution coordination
  - `src/tools/` — tool handlers (bash, read, write, edit, grep, glob, web-search, ask-user-question, update-plan) + `executor.ts`
  - `src/mcp/` — MCP client/manager for external tool servers
  - `src/hooks/` — hooks engine
  - `src/marketplace/` — skill/plugin marketplace manager
  - `src/common/` — providers, openai client/thinking/message-converter, permissions, and other shared utilities
  - `src/prompt.ts`, `src/settings.ts` — system prompt and settings schema
- `packages/cli` (`@YuanyuanMa03/cropcode-cli`) — terminal UI:
  - `src/cli.tsx` — entry point: arg parsing → CLI subcommands (`marketplace`, `plugin`, `update`, `rollback`) → Ink TUI
  - `src/common/update-check.ts` — portable-release self-update: GitHub Releases manifest check, sha256-verified versioned installs, rollback
  - `src/generated/git-commit.ts` — generated by `npm run generate` (runs as part of `bundle`); do not hand-edit
  - `src/ui/views/` — App, AppContainer, PromptInput, PermissionPrompt, SessionList, UpdatePrompt, etc.
  - `src/ui/core/` — non-React terminal logic (slash-commands, prompt buffer/undo-redo, file mentions, thinking state)
  - `src/ui/components/`, `src/ui/hooks/`, `src/ui/contexts/` — smaller UI building blocks
- `scripts/` — esbuild bundling, portable build/packaging, distribution tests
- `docs/` — architecture, configuration, MCP, marketplace, notify docs (Chinese and `_en` English variants)

## Commands

```bash
npm run check              # typecheck + lint + format check (what CI runs)
npm run typecheck          # tsc --noEmit across workspaces
npm run lint               # eslint on packages/*/src and scripts
npm run lint:fix           # eslint --fix
npm run format             # prettier --write
npm run test               # runs tests in all workspaces
npm run test:distribution  # install + run a packaged distribution without system Node.js
npm run build              # core tsc → ESM import rewrite → cli esbuild bundle
npm run start              # run the built CLI (packages/cli/dist/cli.js)
npm run generate           # regenerate packages/cli/src/generated/git-commit.ts
npm run bundle             # generate + esbuild bundle (CLI + core inlined)
npm run bundle:portable    # self-contained portable bundle to dist-portable/
npm run package:all        # portable bundle + package OS distributions
npm run clean              # remove build artifacts
```

Run a single package's tests (test runner discovers `src/tests/*.test.ts` and runs them via `tsx --test`, i.e. node:test):

```bash
npm run test -w @YuanyuanMa03/cropcode-core
npm run test -w @YuanyuanMa03/cropcode-cli
```

Run one test file directly:

```bash
node --import tsx --test packages/core/src/tests/session.test.ts
```

## Environment & Tooling

- Node.js >= 22 per `engines` (`.nvmrc` says `22`); CI additionally tests Node 20 and 24
- ESM everywhere (`"type": "module"`)
- TypeScript strict mode with extra strictness flags (`noUnusedLocals`, `noPropertyAccessFromIndexSignature`, `verbatimModuleSyntax`, `noImplicitOverride`/`Returns`/`This`); use `import type` for type-only imports
- Prettier: double quotes, semicolons, 2-space indent, 120 print width, LF line endings
- Husky pre-commit hook runs lint-staged (eslint --fix + prettier --write on staged files)
- Bundling uses esbuild with shims in `scripts/` (`react-devtools-core` shim, ESM import rewriting); core is inlined into the CLI bundle (`packages: "bundle"`)
- CI (`.github/workflows/ci.yml`): `check` + `bundle` + `test` on 3 OS × Node 20/22/24, plus a distribution-install job per OS (`bundle:portable` → `package-distributions.mjs <target>` → `test:distribution`)

## Architecture Notes

- Entry flow: `packages/cli/src/cli.tsx` → subcommand dispatch → Ink TUI → `AppContainer` → `App`
- CLI subcommands (`marketplace`, `plugin`, `update [--check]`, `rollback`, `--version`, `--help`, `-p <prompt>`) are handled in `cli.tsx` before the TUI launches
- Self-update (`packages/cli/src/common/update-check.ts`): release installs check GitHub Releases for a manifest, install updates into versioned directories with sha256 verification, and preserve user data under `~/.cropcode/`. Startup update checks must never block or interrupt the interactive CLI
- CLI depends on core via the `file:../core` workspace link; core must not depend on cli
- LLM access goes through the OpenAI-compatible client in `packages/core/src/common/openai-client.ts`; provider presets in `provider-presets.ts`; thinking-mode format adaptation (deepseek vs qwen protocols) in `openai-thinking.ts`
- Settings hierarchy: credentials.json (login wizard, highest) → environment variables (`CROPCODE_*`) → `<project>/.cropcode/settings.json` (project) → `~/.cropcode/settings.json` (user) → defaults (see `docs/configuration_en.md`)
- User data (settings, sessions, skills) lives under `~/.cropcode/`
- When adding a new tool: implement a handler in `packages/core/src/tools/`, register it in the executor, and extend the system prompt in `packages/core/src/prompt.ts` if needed
- Docs are maintained in both Chinese and English (`docs/foo.md` + `docs/foo_en.md`); keep them in sync when changing documented behavior
